# ARCHITECTURE — AGY_Aqua_webGPU (новый аквариум)

Технический контракт. Исполнитель: Gemini Carbon (оркестратор `agy`, модель `gemini-pro-orchestrator`, «Orchestrator (Carbon)»). Что строить и ворота приёмки — в [TZ.md](TZ.md). Этот документ — «как»: модули, мир, форматы, граф кадра, виды, бюджеты.

Источник приёмов — Noniv/abyssal-garden @ `a596354` (MIT). **Код не копируем**: приёмы и идеи берём, реализацию пишем с нуля. Если любой фрагмент всё же скопирован — в начало бандла ставится MIT-notice оригинала (см. TZ.md §0).

## 0. Жёсткие ограничения

- Чистый **WebGPU + WGSL**, без движков (Three/Babylon и т.п. запрещены).
- Всё **процедурное**: ни файлов текстур, моделей, шрифтов, звука.
- Deliverable — **один самодостаточный `index.html`**.
- **Ноль аллокаций в JS на кадр**: всё числовое состояние в преаллоцированных типизированных массивах; анимации — чистые функции времени в шейдерах. (GPU-объекты кадра — encoder/view — создаются, это не JS-куча чисел; кэшировать bind groups и pass descriptors.)
- Reverse-Z (`depthCompare: 'greater'`), HDR `rgba16float`, глубина `depth32float`.

## 1. Модули и порядок сборки

Конкатенация в один async-IIFE (порядок важен, как в оригинале `build.mjs:12`):

1. `quality.js` — уровень LV, константы THIN/SHADOW/AA/WATER/RAYN, crash-detection.
2. `math.js` — RNG (seeded), value-noise/fbm/worley, кватернионы, константы сетки, surface nets, sampler3, класс Mesh (sweep/tube/lathe/build), icosphere.
3. `shaders.js` — все WGSL-строки с маркером `/*wgsl*/`.
4. `world.js` — layout (mesas/arches/holes/clears), генерация рельефа и контента, меши видов, инстанс-буферы, 3D-vol, ground-map, **heightmap**.
5. `glyphs.js` — штриховые таблицы 11 глифов «#вайбкодеры», раскладка надписи по дну (новый модуль).
6. `main.js` — рендерер, камера, ввод, коллизия, кадровый цикл, регулятор.
7. `audio.js` — процедурный Web Audio эмбиент (таймер 10 Гц, не кадр).
8. `dev.js` — только в `dev.html`: полёт F, бенчмарк B, фиксированные ракурсы, JSON-отчёт.

Сборка: Node + esbuild; минификация JS и CSS, **минификация WGSL** внутри `/*wgsl*/`-литералов (убрать комментарии, схлопнуть пробелы, вырезать пробелы вокруг операторов). Отчёт о размере и gzip. `npm run build` → `index.html`; `build:dev` → `dev.html` (+dev.js); `build:readable` → без минификации.

## 2. Размеры мира

- Сетка плотности: **NX=512, NY=80, NZ=512, VS=0.75 м**, origin (−192, −56, −192). Мир **384 × 60 × 384 м**, поверхность y=0, дно ~y=−56.
- Водный столб **60 м**. useful глубина камеры y∈[−52, −1.2].
- Сетка отсечения: **CELLS=16, CELLW=24 м** (16×16 по XZ).
- Радиус доступного мира ~150–170 м; кольцо-плато за 156 м скрывает границу.

**Хватает ли 60 м киту — да.** Габарит кита: длина тела **14 м**, размах хвоста **6 м**, амплитуда вертикального маха **±1.5 м**. Коридор плавания кита **y∈[−40, −12]** (28 м по вертикали). Кит горизонтален, вертикальный манёвр требует ~6 м запаса — 28 м коридора достаточно; кит не подходит ни к поверхности (−1.2), ни к дну (−52). Аналогично акулы y∈[−38,−10], кальмары y∈[−18,−6] (ближе к поверхности — нужно для красного цвета, §6.4), крабы по дну.

## 3. Граф проходов кадра

Один command encoder, порядок (как оригинал `main.js:425`, плюс динамическая тень героев):

1. **Вода + мипы.** Анимированная текстура воды (каустика + slope) в mip0, затем 4 mip-прохода (5 mipов всего).
2. **Динамическая тень героев** (только герои + крабы, **~59k трис на LOD0, ≤ 60k**) в depth-текстуру `tShadowDyn` 1024². Статическая тень `tShadow` 4096² запечена на загрузке и НЕ перерисовывается.
3. **Сцена** (MSAA 4× → resolve в HDR):
   1. рельеф (cell-отсечение, до 240 м);
   2. статичные props (камни/губки/кораллы) с LOD;
   3. **надпись** «#вайбкодеры» (инстансы глиф-камней/ракушек, emissive);
   4. **киты** (LOD по дистанции);
   5. **акулы**;
   6. **кальмары**;
   7. **крабы**;
   8. рыбы-косяки (фон);
   9. водоросли 9/5/3 рядов + мелочь;
   10. поверхность воды снизу (окно Снелла);
   11. фон за дальностью (haze 240 м, чтобы не было чёрного);
   12. пузыри (alpha), блики (additive), снег (additive).
4. **Лучи** (volumetric shafts) в **полразрешения**, читают depth + статическую тень + 3D-vol.
5. **Размытие** лучей (depth-aware 3×3).
6. **Bloom**: 6 down + 5 up (additive).
7. **Пост/композит** в swapchain: depth-aware upsample лучей, bloom mix, виньетка, tonemap (ACES-подобный), gamma 2.2, dither.
8. Resolve timestamp-запросов (начало=вода, конец=пост) → GPU-мс кадра.

## 4. Bind groups и форматы буферов

### 4.1 Bind group сцены (group 0), 9 биндингов
| binding | тип | ресурс |
|---|---|---|
| 0 | uniform | `G` (240 Б): vp, sm(тень), cam, right, up, fwd, sun, res, mis |
| 1 | sampler | repeat + anisotropy (8 High / 1 Low) |
| 2 | sampler | clamp linear |
| 3 | sampler_comparison | less-equal (тень) |
| 4 | texture_depth_2d | `tShadow` (статическая тень) |
| 5 | texture_2d<f32> | `tWater` (каустика/slope, 5 mip) |
| 6 | texture_2d<f32> | `tDetail` (1024², 11 mip) |
| 7 | texture_3d<f32> | `tVol` (256×40×256 rg8: openness/skylight) |
| 8 | texture_2d<f32> | `tMap` (512² rgba8: magenta/zone/sand/**height**) |

Дополнительно для героев: binding 9 = `tShadowDyn` (depth, динамическая тень) и binding 10 = `tHeight` (r16float/r32float heightmap для крабов) — либо height кладётся в канал `tMap.a`/отдельный `tHeight`. **Решение: отдельный `tHeight` 512² r32float**, sampling в VS краба.

### 4.2 Вершинные форматы
- **vbSolid = 16 Б**: `float32x3 pos` (offset 0) + `snorm8x4 normal+aux` (offset 12). **Все меши видов (кит/акула/кальмар/краб), рыбы и статичные props используют именно vbSolid (16 Б)** и сливаются в общий vbMesh/ibMesh (§4.3).
- **aux (normal.w) — одна анимационная координата на вершину**, знак кодирует часть меша (snorm8 поддерживает отрицательные):
  - **aux ∈ [0,1]** — продольная/радиальная координата тела (кит: u вдоль тела; кальмар: радиальная координата мантии; краб: **1.0 для карапакса**);
  - **aux ∈ [−1,0)** — придаток: |aux| = span-координата плавника/крыла (кит, акула), координата v вдоль щупальца (кальмар) или координата створки клешни (краб);
  - **ноги краба:** aux = legIndex/8 ∈ [0,0.875] (индекс ноги 0..7, i = round(aux*8)); карапакс aux=1.0 — не пересекается с ногами; фаза ноги выводится в VS из legIndex, не хранится в aux.
  - Для статичных props aux = AO-координата (как оригинал).
- **vbLeaf** не нужен (листья процедурные из vertex_index, инстанс ibLeaf).

## 5. Отсечение и LOD

- CPU: `drawCells` — обход рядов от ближнего к дальнему, AABB+frustum тест клетки, **слитные серии** видимых клеток → один draw call на серию. Дальность масштабируется `det` (кроме рельефа).
- GPU: гашение дальних листьев/бликов в VS по дистанции.
- LOD водорослей: pipeline-константы ROWS 9 (0–24 м) / 5 (24–58) / 3 (58–150); мелочь ROWS 3 FAR 70.
- **LOD героев** по дистанции до камеры: LOD0 (полный) < 30 м, LOD1 < 80 м, LOD2 дальше; переключение выбором меша (v0/i0) в draw call. Кит LOD0 ~6k трис → LOD2 ~400.
- Дальние камни — упрощённые меши на 40–150 м.

## 6. Виды: меш, инстанс, формулы движения, поведение

### 6.0 Общие константы, хелперы и тени (чтобы не угадывать)

**Тени (определения):** `shadow1(p)` = 1-tap `textureSampleCompareLevel` статической карты `tShadow`; `shadow4(p)` = 4-tap PCF (усреднение 4 сэмплов) той же карты. Герои получают статическую тень этими функциями и кастуют в `tShadowDyn`.

**Хелперы (WGSL):** `triangleWave(x) = 1 - abs(2*fract(x) - 1)` (пила 0..1..0); `easeOut(x) = 1 - (1-x)*(1-x)`.

**Базис орбиты (общий для рыб/акул/китов):** `ta = t*omega + phase`; `ph = phase` (инстанс-поле phase, рад); касательная `T = normalize(vec3(-R*sin(ta), vy*cos(ka*ta+ph), R*kz*cos(ta))) * sign(omega)`; боковой `S = normalize(cross(vec3(0,1,0), T))`; вверх `Up = cross(T, S)`. Мировая вершина `w = P + T*l.x + Up*l.y + S*l.z`, нормаль `n = T*n.x + Up*n.y + S*n.z`. (Для рыб vy=6.6, ka=3, kz=0.6; для акул vy=5, ka=2, kz=0.75; для китов vy=vertAmp*0.3*2, ka=2, kz=0.7.)

**Константы движения (WGSL `const`, не инстанс-поля; значения стартовые, Carbon тюнит в воротах):**
| Вид | Константа | Значение | Смысл |
|---|---|---|---|
| кит | flukeFreq | 1.6 | частота маха хвостом (рад/с множитель t) |
| акула | tailFreq | 6.0 | частота боковой волны |
| акула | k | 5.0 | пространственная частота волны по x |
| акула | amp | 0.22 | амплитуда боковой волны (×scale) |
| кальмар | jetRate | = pulseFreq/6.2831853 | частота рывков, синхронизирована с пульсом мантии |
| кальмар | burstLen | 6.0 | длина локального рывка (м) |
| кальмар | drift | 1.5 | медленный дрейф после рывка (м/цикл) |
| кальмар | jetPulse | 0.3 | доля цикла на рывок |
| кальмар | patrolLen | 12.0 | амплитуда патрульного челнока (м, 0..patrolLen) — ограничивает территорию |
| кальмар | patrolRate | 0.05 | частота патрульного челнока |
| краб | stepFreq | 5.0 | частота шагов ног |
| краб | turnRate | 0.15 | амплитуда медленного поворота heading (рад) |

Траектории — аналитические (см. ниже).

**Траектории — АНАЛИТИЧЕСКИЕ (в вершинном шейдере, функции времени+seed), НЕ compute-симуляция.** Обоснование: ноль состояния/аллокаций на кадр, детерминизм, дёшево, без readback и синхронизации — проверено оригиналом (vsFish/vsManta). **Отказались от:** compute-boids/фlocking, CPU-физики, per-frame перезаписи инстанс-буферов — они ломают zero-alloc и добавляют проходы/буферы/синхронизацию без нужды для сценического аквариума. Исключение «посадка на рельеф» у краба решается **сэмплированием heightmap в VS** (тоже аналитика, не симуляция).

### 6.1 Кит (3 особи)
- **Меш:** SDF-примитивы (сужающаяся капсула тела, эллипсоид головы, два лопасти-хвоста, грудные плавники) → **surface nets** на загрузке (приём meshFluke, но целое тело). Бюджет: LOD0 ~6000 трис, LOD1 ~1500, LOD2 ~400. aux по конвенции §4.2: тело u∈[0,1] (для маха), плавники aux<0 (|aux|=span).
- **Инстанс ibWhale = 48 Б (12 f32):**
  - `a: vec4f` = (pathCenter.xyz, R) — центр орбиты и радиус;
  - `b: vec4f` = (omega, phase, scale, seed);
  - `c: vec4f` = (depthY, vertAmp, pitchBias, spare). **depthY** = базовая глубина центра орбиты (м, ∈[−40,−12], задаёт коридор §2); **pitchBias** = статический тангаж тела (рад); **vertAmp** = амплитуда вертикального маха (м, ~1.5); spare = резерв.
  ```wgsl
  struct WhaleI { @location(2) a: vec4f, @location(3) b: vec4f, @location(4) c: vec4f; };
  ```
- **Движение (VS):** орбита `P = vec3(a.x, depthY, a.z) + vec3(R*cos(ta), vertAmp*0.3*sin(2*ta+phase), R*0.7*sin(ta))`, `ta = t*omega + phase`. **Вертикальный мах хвостом:** для вершины тела с aux=u≥0 (хвост при u>0.6): `l.y += vertAmp * pow(max(u-0.55,0)/0.45, 1.5) * sin(t*flukeFreq + phase - u*2.0)` — бегущая волна к хвосту, амплитуда растёт к лопасти. **Грудные плавники** (aux<0, span=|aux|): `fin.y += 0.3*sin(t*0.8 + phase + span)*span`. Тангаж тела = pitchBias + наклон по касательной орбиты (базис T/S/Up как у рыб).
- **Тени:** получает статическую тень (shadow4) + динамическую от других героев; кастует в tShadowDyn.
- **Шейдинг:** тёмно-синяя спина / светлое брюхо (counter-shading), barnacle-пятна noise, блик gloss. Туман общий.

### 6.2 Акула (5 особей)
- **Меш:** лофт ( loft по профилям тела: рыло, туловище, хвостовой стебель) + спинной/грудные/хвостовой плавники (sweep). Бюджет LOD0 ~2500 трис, LOD1 ~700, LOD2 ~200. aux по §4.2: тело — продольная координата ∈[0,1], плавники aux<0 (|aux|=span).
- **Инстанс ibShark = 32 Б (8 f32):**
  - `a: vec4f` = (center.xyz, R);
  - `b: vec4f` = (seed, omega, scale, phase).
  ```wgsl
  struct SharkI { @location(2) a: vec4f, @location(3) b: vec4f; };
  ```
- **Движение (VS):** орбита `P = center + vec3(R*cos(ta), 2.5*sin(2*ta+ph), R*0.75*sin(ta))`, базис T/S/Up — по §6.0 (vy=5, ka=2, kz=0.75, ph=phase). **Боковая бегущая волна по телу:** `l.z += sin(t*tailFreq + seed*50 + l.x*k) * amp * (0.25*scale - l.x)` — амплитуда растёт к хвосту (l.x отрицателен к хвосту), волна бежит по x. Голова почти неподвижна, хвост машет. Поворот нормали вместе с изгибом. Плавники (aux<0) слегка отстают по фазе.
- **Тени:** shadow1 + динамическая; кастует.
- **Шейдинг:** серый верх / белый низ, жаберные щели (полосы по x), блик.

### 6.3 Красный кальмар (8 особей)
- **Меш:** мантия (lathe-конус), голова-сфера, 8 щупалец + 2 ловчих (tube по полилинии), плавники-треугольники. Бюджет LOD0 ~1800 трис, LOD1 ~500, LOD2 ~150. aux по §4.2: мантия радиальная ∈[0,1], щупальца aux<0 (|aux|=v вдоль щупальца).
- **Инстанс ibSquid = 48 Б (12 f32):**
  - `a: vec4f` = (anchor.xyz, mantleLen);
  - `b: vec4f` = (seed, pulseFreq, scale, jetPhase);
  - `c: vec4f` = (dir.xyz, tentacleSpread). **dir — горизонтальный единичный вектор (dir.y=0)**, глубина фиксирована anchor.y ∈[−18,−6]; **jetPhase = seed + 0.25** — рывок приходится на пик сжатия мантии.
  ```wgsl
  struct SquidI { @location(2) a: vec4f, @location(3) b: vec4f, @location(4) c: vec4f; };
  ```
- **Движение (VS):** **пульс мантии:** радиальное сжатие `mantle.r *= mantleLen * (1 - 0.25*pow(0.5+0.5*sin(t*pulseFreq+seed),2))` (mantleLen = a.w задаёт базовый радиус мантии). **Патруль + реактивные рывки (ограниченная территория, без скачков):** кальмар патрулирует отрезок вокруг anchor: `patrol = patrolLen * triangleWave(t*patrolRate + seed)`; локальный рывок (нулевой нетто-сдвиг за цикл): `cyc = t*jetRate+jetPhase; jet = fract(cyc); netAdvance = burstLen - drift*(1-jetPulse); jetLocal = (jet<jetPulse ? easeOut(jet/jetPulse)*burstLen : burstLen - drift*(jet-jetPulse)) - netAdvance*jet`; итог `P = anchor + dir*(patrol + jetLocal)`. jetRate = pulseFreq/TAU — рывок синхронизирован со сжатием мантии. Патруль и jetLocal ограничены → кальмар не уходит из мира. **Щупальца** (aux<0, v=|aux|): `tent.z += sin(t*2 + seed + v*4)*0.15*v*tentacleSpread` (tentacleSpread = c.w задаёт амплитуду/разводку), при рывке щупальца вытягиваются назад (`tent += -dir * v * (jet<jetPulse?1:0)`).
- **Тени:** shadow1; кастует в динамическую.
- **Шейдинг (красный в воде):** albedo `vec3(0.70,0.05,0.06)`. Вода поглощает красный (SIG.r≫SIG.b), на глубине красный исчезает. **Компенсация:** (1) кальмар держится в верхнем столбе y∈[−18,−6], где красный ещё жив; (2) **эмиссия фотофоров** `emi = vec3(0.9,0.1,0.12)*photophoreMask*0.4` — не зависит от солнечного поглощения, читается в синем тумане; (3) локальный fill `+ alb*0.15`. Итог: `c = alb*(E*ndl + amb) + emi + spec`, затем общий fog. На глубине >25 м кальмар не появляется.

### 6.4 Краб (12 особей)
- **Меш:** карапакс (сплюснутый эллипсоид), 8 ног (tube, 3 сегмента) + 2 клешни. Бюджет LOD0 ~1200 трис, LOD1 ~350, LOD2 ~120. aux по §4.2: карапакс aux=1.0, ноги aux=legIndex/8 (i=0..7), **клешни aux<0 (|aux| = координата створки)**; фаза ног выводится в VS из legIndex.
- **Инстанс ibCrab = 48 Б (12 f32):**
  - `a: vec4f` = (homeX, homeZ, groundY0, scale). **groundY0** = запасная высота дна в home (м), используется если сэмпл tHeight вне диапазона/невалиден; в норме Y берётся из tHeight;
  - `b: vec4f` = (seed, walkSpeed, heading, legPhase);
  - `c: vec4f` = (strideLen, bobAmp, spare, spare).
  ```wgsl
  struct CrabI { @location(2) a: vec4f, @location(3) b: vec4f, @location(4) c: vec4f; };
  ```
- **Движение (VS):** **ход боком:** текущая позиция `XZ = home + perpendicular(heading(t)) * strideLen * triangleWave(t*walkSpeed + seed)` (боковой челнок), **медленный поворот** `heading(t) = heading + turnRate*sin(t*0.1 + seed)`. **Посадка на рельеф:** `Y = textureSampleLevel(tHeight, sC, XZ/384+0.5, 0).r` (heightmap; fallback = groundY0), **наклон по нормали:** нормаль из конечных разностей heightmap (4 сэмпла), тело ориентируется по ней (кватернион из нормали). **Фазы ног:** для ноги i (aux=i/8, карапакс aux=1.0) `lift = max(sin(t*stepFreq + legPhase + i*PI/4), 0)`; нога поднимается и переставляется вперёд в фазе lift, опорная — стоит; чередование tetrapod (4 ноги в воздухе). `bobAmp` — лёгкое покачивание карапакса.
- **Тени:** получает статическую тень; кастует в динамическую (краб на дне).
- **Шейдинг:** красно-коричневый/оливковый карапакс, пятна noise, блик клешень.

### 6.5 Фон: рыбы и манты (решение)
- **Рыбы-косяки — ОСТАВЛЯЕМ** (урезано до ~1500 особей, 6 школ). Обоснование: почти бесплатны (инстансинг + VS-анимация), заполняют водный столб и дают масштабный ориентир для китов/акул. Инстанс ibFish 32 Б:
  ```wgsl
  struct FishI { @location(2) a: vec4f, @location(3) b: vec4f; }; // a=(center.xyz,R), b=(seed,omega,scale,phase)
  ```
  Формула (самодостаточно): орбита `P = center + vec3(R*cos(ta), 2.2*sin(3*ta+ph), R*0.6*sin(ta))`, базис T/S/Up по §6.0 (vy=6.6, ka=3, kz=0.6, ph=phase); хвостовая волна `l.z += sin(t*9 + seed*50 + l.x*5)*0.22*(0.25*scale - l.x)`.
- **Манты — УБИРАЕМ.** Обоснование: их нишу медленного парения занимают киты; отдельный меш+пайплайн+буфер мант не окупается при четырёх героях; экономим draw call и бюджет трис. Приём взмаха крыльев переиспользуем в грудных плавниках кита.

## 7. Надпись «#вайбкодеры» по дну

- **11 разных знаков:** `#`, `в`, `а`, `й`, `б`, `к`, `о`, `д`, `е`, `р`, `ы` (10 уникальных букв + #).
- **Глифы задаются кодом как ШТРИХИ** (полилинии-скелеты в клетке [0,1]×[−0.2,1], y вверх, выносные элементы вниз до −0.2), не файлом шрифта. Таблицы штрихов — в `glyphs.js` (см. TZ.md приложение A). Альтернатива SDF отвергнута: штрихи проще инстансить камнями и дешевле.
- **Из чего выложена:** **светящиеся ракушки/камни** (bioluminescent shells) — инстансы ibGlyph вдоль штрихов (dot-matrix из pebbles), emissive голубовато-зелёное свечение `vec3(0.3,0.9,0.8)`, чтобы читалось в синем тумане; контур из тёмных камней. Не просто свечение-текстура — именно объёмные камни/ракушки.
- **Размещение:** 3 копии в разных местах (стартовый бассейн, дно каньона, грот). Высота глифа ~1.5 м, шаг ~1.2 м, длина слова ~13 м. Кладётся на дно по heightmap (как крабы), ориентир по нормали дна.
- **Ракурсы чтения:** (1) сверху-сбоку под углом 30–60° к дну (фиксированный ракурс `POSE_INSCRIPTION`), (2) пролёт над надписью в скриптовом полёте, (3) низкий ракурс вдоль дна с торца слова. Надпись читается слева-направо; кириллица не зеркалится.

## 8. Уровни качества

LV 0 High / 1 Medium / 2 Low (как оригинал quality.js):
- THIN = 1<<LV (каждый 2-й/4-й лист/блик/галька);
- SHADOW = LV?2048:4096 (статическая), tShadowDyn = LV?512:1024;
- AA = LV>1?1:4 (MSAA);
- WATER = LV>1?256:512;
- RAYN = LV>1?12:34 (шаги лучей);
- Low: грубее меши видов (LOD сдвиг), cheaper filtering (anisotropy 1), тени 1-tap, нет теней мелких камней.
- Crash-detection: незавершённая загрузка → уровень ниже на следующем старте; device.lost → reload ниже.

## 9. Бюджеты (из замеров на 1080 Ti, не с потолка)

Оригинал на 1080 Ti @2560×1440 High: **GPU avg 10.83 / p99 14.88 / max 17.96 мс** (evidence/benchmark_raw.json). Регулятор оригинала держит полосу 9.8–13.6 мс. Наши цели для нового аквариума на 1080 Ti @1440p High:

- **GPU-кадр: avg ≤ 11 мс, p99 ≤ 15 мс, max ≤ 18 мс** (60 fps с запасом; не хуже оригинала более чем на ~1 мс avg).
- **Треугольники на кадр:** рельеф ~1.5M видимых + props ~0.5M + герои ≤ 60k (3 кита×6k + 5 акул×2.5k + 8 кальм×1.8k + 12 краб×1.2k ≈ 59k на LOD0, меньше с LOD) + рыбы ~1500×~60 = 90k + надпись ~20k. Итого ориентир **≤ 2.5M трис/кадр** на High.
- **Динамическая тень героев:** ≤ 60k трис в один pass 1024² (НЕ повторять ошибку автора с 45M в статическом bake).
- **Инстансы:** рыбы ≤1500, герои 28, надпись ≤ 3×~600 камней = 1800, водоросли как оригинал (сотни тысяч, cell-отсечение).
- **Draw calls:** слитные серии, ориентир ≤ 120/кадр.
- **Бандл:** оригинал 97.2 КиБ; наш с 4 видами + глифами **≤ 110 КиБ** (минифицированный index.html), gzip ≤ 45 КиБ.
- **Память:** освободить рабочую память генератора после загрузки (цель ~500 МБ как оригинал); коллизия ~2 МБ brick-SDF.

Если бюджет не сходится — сначала снижать det/pix регулятором, затем LOD героев, затем THIN; не превышая GPU-пороги.
