# REPORT — Abyssal Garden: разбор и замеры на GTX 1080 Ti

Краткий отчёт. Полный разбор со ссылками файл:строка — в [ANALYSIS.md](ANALYSIS.md). Сырые данные — в [evidence/](evidence/).
Оригинал: Noniv/abyssal-garden @ `a596354eff400d458bc2aeb9bdf5e0a9734b2bcf` (11 коммитов, MIT).

## Ответы на вопросы

- **Технология.** Чистый WebGPU + WGSL, без движков; HDR `rgba16float`, reverse-Z `depth32float`, MSAA 4× (High). Один самодостаточный `index.html`, всё процедурное, без файлов текстур/моделей/шрифтов/звука.
- **Архитектура.** Один async-IIFE; модули конкатенируются в порядке quality→math→shaders→world→main→audio (+dev). Генерация мира на загрузке, кадровый цикл — ноль числовых аллокаций (состояние в `Float64Array F[32]`).
- **Стек/API.** WebGPU (Dawn/D3D12 на Windows), WGSL, Web Audio, esbuild для сборки. Фича `timestamp-query` для GPU-тайминга.
- **Алгоритмы.** Compute плотности рельефа (SDF-примитивы + fbm/worley) → readback → удаление плавающих кусков flood-fill'ом → surface nets на CPU → bucket-сетка отсечения. Разреженная brick-SDF коллизия (Int8 CG + Uint16 CI). Аналитический туман Beer–Lambert, запечённая тень, 3D-текстура открытости/skylight, каустика, bloom, volumetric rays в полразрешения.
- **Структуры данных.** Плоские типизированные массивы; вершина 16 Б (f32x3 + snorm8x4); инстансы 48/36/32/16 Б; cell-sorted буферы с per-cell диапазонами высот и слитными сериями draw calls.
- **Оптимизации.** Двухуровневое отсечение (CPU-клетки + GPU-гашение дальних листьев), LOD водорослей 9/5/3 рядов и дальние меши, слитные серии инстансов, упаковка нормалей/цветов в 8 бит, освобождение ~500 МБ памяти генератора после загрузки, GPU-timed регулятор разрешения/дальности, ноль аллокаций на кадр.

## Замеры на GTX 1080 Ti (эта машина)

Chrome 157.0.8103.51, D3D12/Dawn. **GPU проверен до замера** через `chrome://gpu`: WebGPU = Hardware accelerated, Dawn = `<Discrete GPU> D3D12 backend - NVIDIA GeForce GTX 1080 Ti`, ACTIVE-адаптер 0x10de/0x1b06; Microsoft Basic Render Driver не активен; WebGPU-проба `vendor:nvidia, architecture:pascal`. Рендер идёт на 1080 Ti, не на Remote Display/софте. (`evidence/chrome_gpu.txt`, `evidence/webgpu_adapter.json`.)

Метод: `npm install && npm run build:dev`, `dev.html` через CDP, viewport 2560×1440 @ DPR 1, пресет High + полный бюджет пикселей, клавиша B = 60-секундный пролёт. Лог — отчёт dev.js; кросс-чек — независимый rAF-логгер.

| Метрика (High, 2560×1440) | avg | p99 | max |
|---|---|---|---|
| **GPU-кадр (timestamp-query), мс** | **10.83** | **14.88** | **17.96** |
| **Кадр (rAF), мс** | **16.82** | **75.80** | **106.80** |

- 3570 кадров за 60.3 с; canvas 2560×1440; уровень High (LV=0).
- Независимый rAF-логгер: avg 16.87 / p99 75.90 / max 106.80 мс — совпадает с dev.js.
- Консоль без GPU-ошибок/исключений; benign: powerPreference ignored on Windows, 404 favicon, AudioContext autoplay (синтетический клик).
- Скриншоты 6 ракурсов (клавиши 1–6): `evidence/pose1..6.png`; кадр пролёта `evidence/fly_mid.png`.

**Интерпретация.** GPU avg 10.83 мс ≈ 92 fps GPU-потолок; кадр avg 16.82 мс ≈ 60 fps — упор в vsync дисплея (~60 Гц RDP), не в GPU. GPU p99/max ровные (14.88/17.96). CPU p99/max 75.8/106.8 мс — редкие длинные кадры (планировщик ОС/RDP), на GPU не отражаются. Автор мерил RTX 5070 Ti ~180 fps @1440p; 1080 Ti примерно вдвое медленнее по GPU, но с запасом относительно 60 Гц.

## Выводы для нашего проекта (AGY_Aqua_webGPU)

1. Берём каркас: один HTML, WebGPU+WGSL, генерация на загрузке, ноль аллокаций на кадр, инстансинг + cell-отсечение + LOD, reverse-Z HDR, запечённая тень + 3D-vol, аналитический туман, bloom, GPU-timed регулятор.
2. Бюджет GPU на 1080 Ti для 60 fps с запасом: **avg ≤ ~11 мс, p99 ≤ ~15 мс** (из наших замеров; оригинал держит полосу 9.8–13.6 мс). Это ориентир для ТЗ, не потолок.
3. Живность оригинала — чистые функции времени без симуляции. Для китов/акул/кальмаров приём годится; крабам нужна посадка на рельеф (карта высот/SDF) — добавляем.
4. Красный кальмар: вода поглощает красный сильнее всего (SIG.r=.058 ≫ SIG.b=.0195) — нужна компенсация (близость к поверхности / локальная подсветка / эмиссия), иначе на глубине он чёрный.
5. Высоты воды 60 м хватает киту при габарите ~12–16 м и коридоре плавания глубже −10 м (фиксируем в ТЗ).
6. Риски автора закладываем в ворота ТЗ: бюджет теней на запекание (45M треугольников роняли GPU телефона), чистка плавающих кусков (124 шт.), фон за дальностью 240 м (чёрный фон), обработка device.lost (issue #7).

## Что не получилось / не измерено / осталось предположением

- **CPU p99/max 75.8/106.8 мс** — причина точно не установлена (предположение: планировщик ОС/RDP-сессии или first-use компиляция шейдеров); GPU при этом ровный. Не измерял отдельно.
- **Абсолютный FPS не снят** как «180 fps» автора: наш дисплей ~60 Гц, кадр упёрся в vsync; GPU-потолок (~92 fps) выведен из GPU avg, не измерен напрямую без vsync.
- **Замеры только на High @2560×1440.** Medium/Low и мобильный путь не измерял.
- **issue #7** — причина (потеря инстанса WebGPU на старте у пользователя) не воспроизведена и не доказана; это предположение по тексту ошибки.
- **README «96 KB»** — расхождение зафиксировано, но почему автор так округлил, неизвестно (предположение: устаревшее значение).
- Бенчмарк проведён через CDP с синтетическими событиями; AudioContext не запускался (autoplay-политика) — звук на производительность не влиял и не измерялся.
